# Детальный тест-план AQA API Testing

## 📋 Обзор

Этот документ содержит детальное описание всех тест-кейсов для автоматизированного тестирования REST API приложения AQA.
Тест-план разработан в соответствии со стандартами QA и покрывает все аспекты функциональности API.

- **Приоритет**: Высокий/Средний/Низкий

## ✅ ПОЗИТИВНЫЕ СЦЕНАРИИ

### 🎯 **TP-001: Позитивный сценарий аутентификации**
**Приоритет**: Высокий | **Тип**: Позитивный | **Метод**: testLogin

**Цель**: Проверить успешную аутентификацию пользователя в системе

**Предусловия**:
- Mock сервер запущен на порту 8888
- Приложение запущено на порту 8080
- API ключ `qazWSXedc` доступен и корректен
- Токен `1234567890ABCDEF1234567890ABCDEF` соответствует формату (32 символа, A-Z0-9)

**Тестовые данные**:
```
X-Api-Key: qazWSXedc
token: 1234567890ABCDEF1234567890ABCDEF
action: LOGIN
```

**Шаги выполнения**:
1. Отправить POST запрос на `http://localhost:8080/endpoint`
2. Установить заголовок `X-Api-Key: qazWSXedc`
3. Установить `Content-Type: application/x-www-form-urlencoded`
4. Установить `Accept: application/json`
5. Передать параметры формы: `token=1234567890ABCDEF1234567890ABCDEF&action=LOGIN`

**Ожидаемый результат**:
- HTTP статус код: `200 OK`
- JSON ответ: `{"result": "OK"}`
- Токен сохранен во внутренней памяти приложения
- Приложение выполнило вызов внешнего API `/auth`

**Критерии успешности**:
- Получен статус 200
- JSON содержит `result: "OK"`
- Нет поля `message` в ответе
