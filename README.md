# Автоматизированное тестирование AQA (API Quality Assurance)

## 📋 Обзор проекта

Этот проект содержит комплексную автоматизацию тестирования для Java Spring Boot приложения с REST API.
Тесты покрывают функциональность аутентификации, авторизации и управления сессиями пользователей.

### 🎯 Цели тестирования
- Проверка корректной работы REST API эндпоинтов
- Валидация бизнес-логики аутентификации и авторизации
- Тестирование обработки ошибок и edge-кейсов
- Обеспечение качества и надежности API

### 🛠 Стек технологий
- **Java 17** - язык программирования
- **JUnit 5** - фреймворк для модульного тестирования
- **REST Assured** - библиотека для тестирования REST API
- **Allure** - генератор отчетов о тестировании
- **Maven** - система сборки и управления зависимостями

## 🚀 Запуск тестирования

### Быстрый старт (рекомендуется)
Используйте готовый лаунчер для полного цикла тестирования:

```bash
# Скомпилируйте и запустите
javac -cp "src/test/java" src/test/java/MainMenu.java
javac -cp "src/test/java" src/test/java/MockServer.java
java -cp "src/test/java" MainMenu
```

### Ручной запуск по шагам

#### 0. Компиляция Mock и меню (см. выше↑)

#### 1. Запуск Mock сервера
Mock сервер имитирует внешний сервис для тестирования:
```bash
java -cp "src/test/java" MockServer
```
✅ Mock сервер запустится на `http://localhost:8888`

#### 2. Запуск тестируемого приложения
```bash
java -jar -Dsecret=qazWSXedc -Dmock=http://localhost:8888/ internal-0.0.1-SNAPSHOT.jar
```
✅ Приложение запустится на `http://localhost:8080`

#### 3. Запуск тестов
```bash
mvn test
```

#### 4. Генерация отчета Allure
```bash
mvn allure:serve
```
Отчет откроется в браузере автоматически.

### Эндпоинты приложения
У тестируемого приложения только один эндпоинт, который принимает на вход POST-запросы вида:
```
POST http://localhost:8080/endpoint
Content-Type: application/x-www-form-urlencoded
Accept: application/json
X-Api-Key: qazWSXedc

token=${token}&action=${action}
```
Для доступа к эндпоинту требуется заголовок `X-Api-Key`.  
Это статический API-ключ, который проверяется приложением при каждом запросе.

token - строка длиной 32 символа, состоящая только из символов A-Z0-9
action - действие пользователя. Всего их три:
* LOGIN - аутентификация. Триггерит отправку запроса /auth на внешний сервис. В случае успеха токен сохраняется во внутреннем хранилище
* ACTION - действие. Триггерит отправку запроса /doAction на внешний сервис. Доступно только для токенов, ранее прошедших LOGIN
* LOGOUT - завершение сессии юзера. Удаляет токен из внутреннего хранилище

### Формат ответов
**Успешный ответ:**
```json
{
  "result": "OK"
}
```

**Ответ с ошибкой:**
```json
{
  "result": "ERROR",
  "message": "reason"
}
```

## 🔧 Возможные ошибки

### Проблема: "Port 8080 is not listening"
**Решение:**
1. Проверьте, что приложение запустилось: `tail -f app.log`
2. Убедитесь, что порт 8080 свободен: `netstat -ano | findstr :8080`
3. Проверьте Java версию: `java -version`

### Проблема: "Port 8888 is not listening"
**Решение:**
1. Проверьте запуск Mock сервера: `tail -f mock.log`
2. Убедитесь, что порт свободен
3. Перезапустите Mock сервер

### Проблема: "Tests failed"
**Решение:**
1. Проверьте логи: `mvn test -Dtest=EndpointE2ETest -DforkCount=0`
2. Убедитесь, что все сервисы запущены
3. Проверьте корректность API ключа

### Проблема: "Allure report not opening"
**Решение:**
1. Установите Allure CLI: `npm install -g allure-commandline`
2. Или используйте Maven плагин: `mvn allure:serve`
